1. HIGH-LEVEL SUMMARY: WHAT IS THE MODEL & WHY LOGISTIC REGRESSION?
================================================================================

SpamShield uses LOGISTIC REGRESSION as its primary machine-learning algorithm.
Although the name contains "regression", it is a supervised CLASSIFICATION algorithm 
used to predict the probability that a given input text belongs to one of two 
discrete categories:
  - Class 0: HAM (Legitimate personal, official, or casual message)
  - Class 1: SPAM (Commercial spam, phishing scam, lottery fraud, malware bait)

WHY LOGISTIC REGRESSION WAS CHOSEN FOR TEXT SPAM FILTERING:
1. Strictly Convex Optimization:
   The Binary Cross-Entropy loss function has no local minima. Batch Gradient Descent 
   is mathematically guaranteed to find the global optimal parameter weights.
2. Calibrated Probabilities:
   Unlike Naive Bayes (which assumes features are strictly independent and produces 
   artificially extreme 0.0 or 1.0 probabilities), Logistic Regression optimizes the 
   Bernoulli log-likelihood, outputting genuine posterior probabilities P(Spam|X).
3. Exact Mathematical Explainability:
   Because the model is linear in the log-odds space, every word's contribution can 
   be computed directly as (Weight * Value), showing users exactly why a message was 
   flagged.
4. Production Efficiency:
   Inference is a single vector dot product plus a scalar sigmoid calculation:
   O(d) complexity where d is the number of non-zero tokens. Latency is < 3 milliseconds, 
   making it ideal for telecom-scale message stream filtering.

2. MATHEMATICAL WORKING PRINCIPLE (STEP-BY-STEP EQUATIONS)
================================================================================

Let:
  - x = [x_1, x_2, ..., x_d]^T be the d-dimensional feature vector of a message.
  - w = [w_1, w_2, ..., w_d]^T be the learned coefficient/weight vector.
  - b = the scalar intercept (bias term).
  - y in {0, 1} be the true target class.

--------------------------------------------------------------------------------
STEP A: Linear Combination (Logit / z)
--------------------------------------------------------------------------------
The algorithm first computes the linear dot product of the input features and their 
associated weights, adding the bias:

    z = (w^T * x) + b = sum_{j=1}^{d} (w_j * x_j) + b

The value of z can range anywhere along the real number line: (-infinity, +infinity).
- A large positive z indicates strong spam signals.
- A large negative z indicates strong legitimate/ham signals.

--------------------------------------------------------------------------------
STEP B: Sigmoid Activation Function (Mapping z to Probability)
--------------------------------------------------------------------------------
To map the unbounded score z into a valid probability interval P in (0, 1), the 
model applies the Sigmoid (Logistic) function sigma(z):

    P(Y = 1 | x) = sigma(z) = 1 / (1 + e^(-z))

Properties of the Sigmoid function:
  - When z -> +infinity, e^(-z) -> 0, so sigma(z) -> 1.0 (Certain Spam)
  - When z = 0, sigma(0) = 1 / (1 + 1) = 0.50 (Equally likely)
  - When z -> -infinity, e^(-z) -> +infinity, so sigma(z) -> 0.0 (Certain Ham)

Numerical Safeguard (Implemented in Scratch Model):
To prevent 64-bit floating-point overflow when computing e^(-z), z is numerically 
clipped into [-500.0, 500.0]:
    z_clipped = np.clip(z, -500.0, 500.0)

--------------------------------------------------------------------------------
STEP C: The Odds Ratio and Log-Odds (Logit Formulation)
--------------------------------------------------------------------------------
The "Odds" of a message being spam is the ratio of spam probability to ham probability:

    Odds = P / (1 - P)

Taking the natural logarithm of both sides yields the Log-Odds (Logit):

    ln( P / (1 - P) ) = ln( (1 / (1 + e^-z)) / (e^-z / (1 + e^-z)) )
                      = ln( 1 / e^-z )
                      = ln( e^z )
                      = z = w^T * x + b

This proves that Logistic Regression models the LOG-ODDS of the positive class as 
a purely linear function of the input features!

--------------------------------------------------------------------------------
STEP D: Objective Cost Function (Binary Cross-Entropy with L2 Regularization)
--------------------------------------------------------------------------------
For a dataset of m training examples {(x^(1), y^(1)), ..., (x^(m), y^(m))}, the model 
parameters (w, b) are learned by minimizing the Binary Cross-Entropy (Log-Loss) 
penalized with an L2 Ridge regularization term:

    J(w, b) = - (1/m) * sum_{i=1}^{m} [ y^(i) * ln(y_hat^(i)) + (1 - y^(i)) * ln(1 - y_hat^(i)) ]
              + (lambda / (2*m)) * ||w||_2^2

Where:
  - y^(i) is the true binary label (0 or 1).
  - y_hat^(i) = sigma(w^T * x^(i) + b) is the predicted spam probability.
  - lambda is the L2 regularization hyperparameter.
  - ||w||_2^2 = sum_{j=1}^{d} (w_j^2) penalizes large weights, preventing overfitting.

To prevent ln(0) errors during calculation, y_hat is clipped:
    y_hat_safe = np.clip(y_hat, 1e-15, 1.0 - 1e-15)

--------------------------------------------------------------------------------
STEP E: Analytic Gradient Derivation & Parameter Updates
--------------------------------------------------------------------------------
Using the chain rule, the gradient of the cost function with respect to weights w 
and bias b is:

    dJ / dw = (1/m) * X^T * (y_hat - y) + (lambda / m) * w
    dJ / db = (1/m) * sum_{i=1}^{m} (y_hat^(i) - y^(i))

In Batch Gradient Descent, weights are updated iteratively at every epoch k:
    w^(k+1) = w^(k) - alpha * (dJ / dw)
    b^(k+1) = b^(k) - alpha * (dJ / db)

Where alpha is the learning rate (set to alpha = 0.8 in our scratch model).

--------------------------------------------------------------------------------
STEP F: Decision Rule & Threshold Tuning
--------------------------------------------------------------------------------
Once P(Spam | x) is computed:
  - If P >= tau:  Predict SPAM (1)
  - If P < tau:   Predict HAM (0)

While default classifiers use tau = 0.50, our pipeline performed empirical 
threshold optimization across tau in [0.05, 0.95]. 
The optimal threshold was found at tau = 0.60, which maximizes the F1-Score (0.9524) 
and reduces the False Positive Rate to 0.44%.

3. END-TO-END NLP FEATURE ENGINEERING PIPELINE (TEXT -> NUMBERS)
================================================================================

Raw text cannot be fed directly into mathematical equations. The project passes 
every message through a composite feature extraction pipeline:

1. Text Cleaning & Semantic Token Mapping (src/preprocessor.py):
   Generic NLP systems strip punctuation and symbols. In spam filtering, punctuation 
   and symbols are critical indicators. We map them to distinct tokens:
     - Web Links & URLs             ->  __url__
     - Phone / Helpline numbers     ->  __phone__
     - Currency Signs (£, $, ₹, rs) ->  __currency__
     - Exclamation Bursts (!!!, ??) ->  __exclburst__
     - Arbitrary numbers            ->  __number__

2. N-Gram TF-IDF Vectorizer:
   Computes Term Frequency times Inverse Document Frequency for:
     - Unigrams: single words ("win", "free", "claim", "urgent", "cash")
     - Bigrams: 2-word combinations ("cash prize", "call now", "urgent call")
   Settings:
     - ngram_range = (1, 2)
     - max_features = 4,000
     - min_df = 2 (prunes unique typos appearing only once)
     - sublinear_tf = True (applies 1 + ln(tf) to prevent word spamming skew)

3. Domain Syntactic Meta-Features (13 Quantitative Structural Features):
   - char_count          : Total character length (Spam average: 137, Ham average: 71)
   - word_count          : Number of tokens
   - uppercase_count     : Number of capital letters
   - uppercase_ratio     : uppercase_count / char_count (Spam has high ALL-CAPS ratio)
   - digit_count         : Count of numeric digits
   - digit_ratio         : digit_count / char_count
   - currency_count      : Frequency of monetary symbols
   - url_count           : Frequency of embedded web links
   - phone_count         : Frequency of telephone number patterns
   - exclamation_count   : Count of '!'
   - question_count      : Count of '?'
   - exclamation_burst   : Occurrences of repeated '!!'
   - has_urgent_keyword  : Binary flag for urgent trigger terms (win, prize, claim, etc.)

4. Feature Union:
   The sparse TF-IDF matrix (4,000 features) is stacked with the scaled meta-features 
   (13 features) using StandardScaler(with_mean=False) to create a final 
   feature matrix of shape (M, 4013).

4. DUAL IMPLEMENTATION DETAILS (SCRATCH VS. SCIKIT-LEARN)
================================================================================

--------------------------------------------------------------------------------
A. From-Scratch Logistic Regression (src/models/scratch_logistic_regression.py)
--------------------------------------------------------------------------------
- Built purely using Python and NumPy standard operations.
- Compatible with both scipy.sparse.csr_matrix and dense numpy.ndarray.
- Solved using Vectorized Batch Gradient Descent:
    * Learning Rate (alpha) = 0.8
    * Epochs = 1,200
    * L2 Regularization (lambda) = 0.005
    * Convergence Tolerance = 1e-7
- Tracks full loss history trajectory: J(w,b) converged smoothly from 0.693 down to 0.067.
- Complete serialization to JSON: saves weights, bias, hyperparameters, and vocab.

--------------------------------------------------------------------------------
B. Scikit-Learn Logistic Regression Pipeline (src/models/sklearn_logistic_regression.py)
--------------------------------------------------------------------------------
- Integrated into a production Pipeline([("feature_engineering", ...), ("classifier", ...)]).
- Solver: 'lbfgs' (Limited-memory Broyden-Fletcher-Goldfarb-Shanno)
    * Uses a quasi-Newton second-order optimization technique.
    * Approximates the inverse Hessian matrix H^-1 from past gradient evaluations.
    * Achieves superlinear convergence in fewer iterations.
- Class Weighting: 'balanced'
    * Automatically computes inverse frequency weights: w_c = N / (2 * N_c).
    * Prevents the majority class (87.5% Ham) from overwhelming the 12.5% Spam class.
- Serialized to disk as 'models/spam_classifier_pipeline.joblib'.

5. REAL-TIME EXPLAINABILITY ENGINE (LOG-ODDS DECOMPOSITION)
================================================================================

Implemented in 'spamshield_web/detector/services.py':

Because Logistic Regression models the logit linearly:
    logit(P) = w_0 + sum_{j=1}^{d} (w_j * x_j)

For any specific message being classified:
  - Each individual feature j contributes an exact additive shift: Delta_j = w_j * x_j.
  - If Delta_j > 0: The feature pushes the probability toward SPAM (shown in Red).
  - If Delta_j < 0: The feature pushes the probability toward HAM / Safe (shown in Green).

7. ACADEMIC VIVA DEFENSE: KEY CONCEPTUAL QUESTIONS & ANSWERS
================================================================================

Q1: What is the cost function of Logistic Regression and why is MSE not used?
A1: Logistic Regression uses Binary Cross-Entropy (Log-Loss):
    J = -1/m * sum[ y * ln(y_hat) + (1-y) * ln(1-y_hat) ].
    Mean Squared Error (MSE) is not used because combining MSE with the non-linear 
    Sigmoid function produces a non-convex surface full of local minima. 
    Log-Loss is derived from Maximum Likelihood Estimation and is guaranteed to be 
    strictly convex, ensuring gradient descent reaches the global minimum.

Q2: Why is False Positive Rate (FPR) much more critical than Recall in spam detection?
A2: A False Negative lets a spam message into the inbox (a minor annoyance). 
    A False Positive marks an important legitimate message (bank OTP, hospital report, 
    job offer) as spam or drops it entirely (a critical failure). 
    Therefore, our model is tuned to maintain an FPR below 0.5%.

Q3: How did you address the 87.5% Ham vs 12.5% Spam class imbalance?
A3: Four techniques were used:
    1. Stratified train/test split (stratify=y) preserving proportions.
    2. Cost-sensitive weighting (class_weight='balanced') scaling minority loss.
    3. Decision threshold optimization (tuning tau from 0.50 to 0.60).
    4. Evaluating via Precision, Recall, F1, and PR-AUC instead of raw accuracy alone.

Q4: What is the difference between Batch Gradient Descent and L-BFGS?
A4: Batch Gradient Descent is a first-order optimizer that updates parameters using 
    only the first derivative (gradient vector). It requires many iterations to converge. 
    L-BFGS is a second-order quasi-Newton optimizer that approximates the curvature 
    (inverse Hessian matrix) using past gradient vectors, achieving superlinear 
    convergence in substantially fewer steps.

Q5: What happens when the SMS-trained model is tested on SpamAssassin emails?
A5: It demonstrates "Domain Shift". The model achieves 99.7% recall on email spam 
    because trigger words ("free", "winner", currency signs) transfer across domains. 
    However, false positives increase because raw emails are 20x longer than SMS messages, 
    causing length and digit meta-features to trigger false alarms. 
    This is why email and SMS datasets must never be blindly merged during training.
